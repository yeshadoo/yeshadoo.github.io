## Agency 来自模型,Agent 产品 = 模型 + Harness

Agent 这个词被一整个提示词水管工产业劫持了。拖拽工作流、节点图、把 LLM 调用串成 if-else —— 这些不是 Agent,是有宏大妄想的 shell 脚本。

真正的 Agency —— 那种感知、推理、行动的能力 —— **来自模型训练,不是来自外部代码的编排**。DQN、AlphaStar、OpenAI Five、绝悟、Claude,架构都一样:一个训练好的模型 + 一个能让它在特定环境工作的基础设施。

模型是驾驶者,Harness 是载具。

当一个工程师说「我在开发 Agent」,只可能是两个意思之一:

1. **训练模型** —— 改权重、收集任务过程数据、做 RL/RLHF。这是 Anthropic、OpenAI、DeepMind 在做的事。
2. **构建 Harness** —— 给模型提供一个可操作的环境。这是绝大多数人在做的事。

承认自己是在做后者,不会显得弱 —— 反而是看清自己工作真正杠杆点的开始。

## Harness 工程师到底在做什么

抽干水分,Harness 就是这五件事:

```
Harness = Tools + Knowledge + Observation + Action Interfaces + Permissions
```

- **Tools**:给 agent 一双手 —— 文件读写、Shell、API、浏览器、数据库
- **Knowledge**:给 agent 领域专长 —— 文档、规范、决策记录、风格指南
- **Observation**:给 agent 一双眼 —— diff、日志、监控、传感器
- **Action**:行动通道 —— CLI、API、UI 交互
- **Permissions**:边界 —— 沙箱、审批、信任分级

模型做决策,Harness 执行;模型做推理,Harness 提供上下文。这件事在编程领域的最优雅落地,就是 Claude Code。

## 一个真实案例:ad-creative 的 Harness 转型

以下是我手上一个项目的实际经历。背景是阿里妈妈广告创意系统(`ad-creative`),Java/Spring 多模块,业务复杂度高 —— 表达层/投放层分层、父子级联审核、多标审核、风控回调、AIGC 素材链路。AI 编程助手在这种代码库上幻觉严重,一开始几乎用不起来。

转型的目标不是「再造一个 agent」,而是把这个代码库改造为 **agent 友好的开发环境**。具体做了四块事。

### 一、工具层:接口的统一封装与多形态暴露

工具层的核心认知是一个反直觉的视角转换:

> 传统接口是给工程师调的(假设读过文档),Agent 接口是给模型调的(只有 schema + description)。**Tool Design 就是 Prompt Design。**

所以工具层不是「把 HSF 接口包成 MCP」这种体力活。重点在三处:

#### 工具粒度按 agent 推理边界拆,不按代码模块拆

Agent 在一个推理 step 内要回答的问题,决定了一个工具的边界。我们的 `get_creative_full_state` 工具内部聚合了创意主数据 + 审核状态 + 父子关系 + 灰度状态 —— 因为 agent 在判断「这个创意为什么投不出去」时,**这四样必须放在同一个上下文窗口里看,拆开调反而引入推理跳跃**。反过来,创意修改和素材修改要拆开,因为它们的决策路径不同。

工具不是接口的一一映射,是 agent 推理图的边。

#### 返回结构是 context 工程,不是数据传输

工具返回什么 = agent 下一步推理质量。三个具体设计:

- **业务视角而非数据库视角**:返回不能直接吐 DO/PO,要按术语对账表翻译成业务概念(`audit=true` → "审核表数据")
- **错误要可推理**:不抛 stack trace,而返回 `{"error": "no_data", "hint": "查询走的是审核表,试试切换到投放表"}` —— 错误本身要给恢复方向
- **字段名直接是 prompt**:`is_express_creative` 永远比 `parentId == null` 强,因为它对齐了 agent 的概念图

返回 JSON 的每个字段都在消耗 agent 的 attention。冗余字段是污染,精简字段是赋能。

#### 调用形态服从场景

| 形态 | 适用场景 |
|---|---|
| MCP server | 跨 agent / 跨工具复用的核心能力 |
| Skill + script | 步骤化、模板化、带知识依赖(如 ODPS 取数) |
| 原生 tool_use | 文件、Shell、HTTP 等基础原子操作 |
| HSF Adapter | 接入外部异构系统的稳定通道 |

不为 MCP 而 MCP,也不为 skill 而 skill。

### 二、知识层:11 个领域 Skill + 入口对账 + 防腐机制

知识不是堆文档,关键是**索引前置、内容懒加载**:

- **入口层**:`AGENTS.md` —— 项目分层、术语对账(表达创意/投放创意、表达素材组/投放素材组、级联计算)、硬规范(灰度开关、父子更新顺序、审核表→投放表同步)
- **领域层**:11 个 SKILL —— 业务总览、审核状态级联、父子关系、表达/投放层数据变更、AIGC 素材生产、SQL/ODPS 取数等。主上下文只放索引,内容按 description 触发词拉入
- **治理层**:`knowledge-diff-check` CR rule —— 代码改动自动检测是否触及 skill 文档,失效则生成结构化 diff 报告等待人工 review 后更新

最后一条最关键。**没有这一层,知识库会以肉眼可见的速度腐烂**。

### 三、创意诊断 Skill:为什么必须用多 Agent

这块特别想展开,因为我最初的版本就是单 Agent —— 跑下来踩了三个坑才改的。

**坑一:上下文污染**

诊断要跨 6 个维度(审核状态、父子级联、风控回调、AIGC 链路、投放表同步、灰度状态)。单 Agent 意味着前置加载 7-8 个 SKILL 到主上下文,**业务知识淹没了推理空间**。模型确实「读」了所有内容,但关键判断会被无关知识干扰 —— 同一个创意诊断,跑 5 次有 2 次会把扩展字段的语义搞混。

换成 subagent 派生后,主 Agent 只接收结构化结论,主上下文压到 5k token 以内,稳定性立刻上去。

**坑二:噪声不能传染**

诊断里很多子步骤会失败:SQL 查不到数据、HSF 超时、trace 缺失。单 Agent 做,这些错误消息和中间推理会全留在主上下文,模型会在那个查不出的字段上反复纠结。

Subagent 把每个子任务装进独立上下文,失败就失败,主 Agent 拿到的是「此项无数据」的结构化结论,继续往下走。

**坑三:复用粒度**

单 Agent 实现把诊断逻辑和主 prompt 强耦合在一坨。拆成 subagent 后,每个子诊断本身就是独立可调用单元 —— 「审核状态追溯」可以被答疑工单系统单独调用,不必走完整诊断流程。

#### 关键认知

> **subagent 不是为了「分工」,而是为了「隔离上下文」。**

模型能力再强,只要 attention 是有限资源,把无关上下文塞进去就一定会稀释关键判断。这是结构性问题,**不是靠换更强的模型能解决的**。

反过来也得承认 —— 不是所有诊断都该上多 Agent。简单查询用一个 Agent + 两三个工具就够了,套 subagent 是过度设计。我们的内部判断标准:**当输入需要交叉 3 个以上独立领域知识才能给结论时,才派生 subagent**。

### 四、验证与交付 Harness:把瓶颈从「写代码」推到「让代码可信上线」

代码生成已被模型解决,真正的成本集中在测试、CR、部署。**这是 agent 工程下一阶段的主战场。**

- **测试生成 Skill**:以 `git diff` + 涉及的领域 skill 为输入,自动产出覆盖关键路径的测试用例。**知识库做 oracle,模型做填空** —— 显著降低用例幻觉
- **CR Agent**:在 `knowledge-diff-check` 基础上扩展 N 条规则(灰度开关漏写、父子更新顺序、审核表同步遗漏、HSF 兼容性、扩展字段滥用)。业务规范从「人工记得」变成「机器拦截」
- **部署 Harness**:线性 mvn 脚本 → agent 可调度流程,每步带验证,失败可决策(重试/跳过/回滚)
- **线上回归闭环**:复用诊断 Skill 作为部署后探针,自动跑黄金集,异常自动告警/回滚

这一套连起来,才能让团队从「不敢让 agent 写主链路」转向「主链路 agent 写、人 review」。

## 收尾:一句话总结

Harness 工程师的价值不在写更复杂的流程图,**而在给模型一个干净、强大、有边界的工作环境**:

- 工具要锋利
- 知识要清洁
- 上下文要隔离
- 交付要可信

模型负责智能,Harness 负责放大智能。

这套方法论可以泛化到任何垂直域的 agent 系统 —— 农业、酒店、医疗、制造,都是同一个模式。先铺满工作室,然后是农田、医院、工厂,然后是城市,然后是星球。

**Bash is all you need. Real agents are all the universe needs.**
